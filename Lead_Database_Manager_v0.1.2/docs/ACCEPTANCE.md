# Приёмка v0.2.0

## Проверки кода
- Worker syntax check.
- Все JS-модули syntax check.
- Node test runner: auth, API access guard, health, Telegram webhook validation.
- SQLite: обе миграции применяются последовательно.
- SQLite: telegram_id уникален.
- SQLite: один лид может состоять в нескольких сегментах.
- SQLite: удаление сегмента не удаляет лидов.

## Проверки в Cloudflare после настройки
1. `/api/health` сообщает `database: connected`.
2. `/api/auth/config` сообщает `admin_token_configured: true`.
3. Вход с правильным `ADMIN_TOKEN` успешен, неверный ключ отклоняется.
4. Создание лида возвращает новую запись.
5. Повторное создание того же Telegram ID обновляет запись, не создавая дубликат.
6. Список лидов использует `page`, `page_size`, `q`, `status`, `quality`, `segment_id` на сервере.
7. Редактирование и удаление сохраняются после обновления страницы.
8. Один лид можно добавить в несколько разделов.
9. Удаление раздела не удаляет лидов.
10. Массовые действия корректны.
11. Основные операции появляются в журнале.

## Ограничение автоматической проверки
Тестирование в локальном контейнере подтверждает синтаксис и поведение SQL на SQLite. Оно не заменяет проверку фактического D1 binding и публикации в аккаунте Cloudflare владельца. Эти шаги требуют его браузерной настройки.
