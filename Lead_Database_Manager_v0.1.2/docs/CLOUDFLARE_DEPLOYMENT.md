# Развёртывание v0.2.0 через браузер (без локальных установок)

## 1. GitHub

1. Распакуйте ZIP на компьютере.
2. Загрузите **содержимое** архива в корень репозитория. В корне должны лежать `wrangler.jsonc`, `package.json`, `public/`, `src/`, `migrations/` и `docs/`.
3. Если проект сознательно хранится во вложенной папке, укажите её имя в Workers Builds → Root directory. Корнем приложения должна быть папка, в которой расположен `wrangler.jsonc`.
4. Сохраните изменения в GitHub.

## 2. Workers Builds

В настройках подключённого проекта:

- Root directory: `/` (если `wrangler.jsonc` находится в корне репозитория; иначе — имя вложенной папки проекта).
- Build command: пусто.
- Deploy command: `npx wrangler deploy --config ./wrangler.jsonc`.

Cloudflare выполняет Wrangler в своей сборочной среде. На пользовательском компьютере Wrangler не нужен.

## 3. D1 создаётся конфигурацией Worker

В `wrangler.jsonc` уже объявлен D1 binding:

- Variable name: `DB`.
- Database name: `lead-database-manager-db`.

При первом deploy Workers Builds / Wrangler должен автоматически создать D1-ресурс и привязать его к Worker. Это механизм automatic provisioning Cloudflare. После deploy откройте Cloudflare → Storage & databases → D1 и проверьте наличие базы `lead-database-manager-db`.

Не создавайте второй D1 с тем же назначением и не добавляйте отдельный binding вручную, пока не проверили результат первого deploy. Конфигурация Wrangler является источником правды о bindings проекта.

Если база с таким именем уже существует в аккаунте до первого deploy и Cloudflare сообщает о конфликте, не удаляйте её. Понадобится добавить её фактический database_id в `wrangler.jsonc`; в этом случае передайте мне ID из карточки D1 (сам ID не является секретом).

## 4. Применить миграции через SQL Console

1. Откройте созданную D1 `lead-database-manager-db`.
2. Перейдите во вкладку **Console / SQL Console**.
3. Откройте в GitHub файл `migrations/0001_stage1_prototype.sql`, скопируйте всё содержимое, вставьте в SQL Console и нажмите **Execute**.
4. Затем откройте `migrations/0002_core_management.sql`, скопируйте всё содержимое, вставьте в SQL Console и нажмите **Execute**.
5. Убедитесь, что обе миграции завершились без ошибок. В `schema_migrations` должны находиться версии `0001_stage1_prototype` и `0002_core_management`.

Миграция `0002` повторно безопасна: создание таблиц и индексов использует `IF NOT EXISTS`, начальные разделы и версия схемы — `OR IGNORE`. `0001` также использует безопасное создание таблиц и индексов.

## 5. Добавить административный ключ

1. Откройте Worker → **Settings → Variables and Secrets**.
2. Нажмите **Add** → **Secret**.
3. Variable name: `ADMIN_TOKEN`.
4. В качестве значения задайте собственный случайный ключ длиной не менее 32 символов (рекомендуется 48–64 символа, символы латиницы, цифры, `_` и `-`). Используйте менеджер паролей или встроенный генератор ключей.
5. Сохраните и выполните Deploy.

Не публикуйте этот ключ в GitHub, исходниках, сообщениях или скриншотах. В браузере он хранится только в `sessionStorage` текущей сессии.

## 6. Проверка

1. Откройте публичный адрес Worker.
2. Введите значение `ADMIN_TOKEN`.
3. Перейдите в **База лидов** и создайте тестовую запись с числовым Telegram ID.
4. Обновите страницу — запись должна остаться в базе.
5. Откройте запись, измените имя или статус и сохраните.
6. Создайте раздел, затем добавьте в него лид из карточки.
7. Проверьте фильтр по разделу и журнал операций.
8. Удалите тестовую запись после проверки, если она больше не нужна.

## 7. Telegram (необязательно на этом этапе)

Для подключения бота отдельно добавьте как Worker Secrets:
- `TELEGRAM_BOT_TOKEN` — токен BotFather.
- `TELEGRAM_WEBHOOK_SECRET` — случайная строка 32–128 символов из латиницы, цифр, `_` и `-`.
- `SETUP_TOKEN` — другой случайный ключ не короче 32 символов.

После Deploy откройте раздел Telegram в приложении, введите `SETUP_TOKEN` и нажмите «Зарегистрировать webhook».

## 8. Локальный просмотр

Откройте `START_HERE.html` и затем `public/index.html`. В локальном режиме отображаются только синтетические данные, хранящиеся в localStorage браузера. Настоящие D1 и Telegram доступны только по опубликованному адресу.
