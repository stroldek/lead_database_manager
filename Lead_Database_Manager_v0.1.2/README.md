# Lead Database Manager v0.2.0

Рабочая версия с управлением лидами и разделами через Cloudflare Worker + D1. Проект не требует установки инструментов на компьютер владельца: исходники загружаются в GitHub, сборка выполняется Cloudflare Workers Builds, D1 и секреты настраиваются через браузерный Dashboard.

## Что работает в v0.2.0

- защищённый вход по секрету `ADMIN_TOKEN`;
- проверка доступности Worker и D1;
- создание, просмотр, редактирование и удаление лидов;
- уникальность Telegram ID на уровне D1;
- серверная пагинация на 25 / 50 / 100 записей;
- поиск по Telegram ID, username, имени, фамилии и источнику;
- фильтрация по статусу, качеству и разделу;
- создание, переименование и удаление разделов;
- связь «многие ко многим»: один лид может входить в несколько разделов;
- массовое изменение статуса и качества, добавление / удаление из раздела, удаление;
- журнал основных операций;
- отдельный локальный DEMO-режим с синтетическими записями;
- Telegram webhook и механизм согласия из предыдущего прототипа сохранены.

## Важно про локальный DEMO

Откройте `START_HERE.html`, затем нажмите «Открыть локальный DEMO». В нём можно проверить интерфейс и операции на синтетических данных. DEMO хранит изменения только в локальном хранилище браузера. Он не является подключением к Cloudflare D1.

## Стек

- Frontend: HTML, CSS, vanilla JavaScript.
- Backend: Cloudflare Worker.
- Database: Cloudflare D1 (SQLite).
- Static assets: Cloudflare Workers Static Assets.
- External dependencies at runtime: отсутствуют.

## Структура

```text
public/       интерфейс
src/          Worker и серверные модули
migrations/   SQL-миграции D1
docs/         инструкции, архитектура и приёмка
tests/        автоматические тесты
wrangler.jsonc конфигурация Worker и Static Assets
package.json  метаданные и команда Deploy
```

## Развёртывание

Смотрите `docs/CLOUDFLARE_DEPLOYMENT.md`. Владелец использует только браузерные панели GitHub и Cloudflare. Не запускайте сборку на своём ПК и не устанавливайте Node.js, Python, Docker или Wrangler.

## Ограничения версии

- На данном этапе поддерживается один административный ключ `ADMIN_TOKEN`, а не многопользовательские аккаунты.
- Импорт / экспорт CSV, XLSX и JSON — следующий этап.
- Telegram сбор работает только в пределах доступных API и согласия пользователей.
- Автоматическая отправка сообщений произвольным пользователям не реализуется.
- Нагрузочный тест на 100 000 записей ещё не проведён.
