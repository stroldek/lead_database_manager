# CHANGELOG

## 0.1.2 — 2026-11-12

### Исправление Cloudflare deployment
- Перепакован ZIP: содержимое проекта теперь находится в корне архива, без лишней внешней папки.
- `wrangler.jsonc` однозначно указывает `main: ./src/worker.js` и `assets.directory: ./public/`.
- Добавлен явный deploy command с `--config ./wrangler.jsonc`.
- Убран фиктивный `REPLACE_WITH_D1_DATABASE_ID`: первоначальный деплой Worker не блокируется отсутствием ещё не созданной D1.
- Добавлена отдельная инструкция по настройке Root directory и Deploy command в Cloudflare Workers Builds.
- Обновлены версия интерфейса и метаданные сборки.

### Сохранено из 0.1.1
- Browser-only local preview через `START_HERE.html`.
- Worker API для health-check и Telegram webhook.
- Подтверждение согласия через inline-кнопку.
- Команда `/stop` для отзыва согласия.
- Защита от повторной обработки Telegram update.
- SQL-миграция и архитектурная документация.


## 0.1.1 — 2026-11-12

### Исправлено в поставке
- Добавлен `START_HERE.html` для запуска предпросмотра двойным щелчком.
- Исправлены пути CSS/JS для открытия проекта по `file://`.
- Добавлен явно обозначенный offline preview без фальшивого статуса Worker/D1/Telegram.

- Уточнено, что Wrangler и сборка работают в удалённой среде Cloudflare при GitHub deployment.

## 0.1.0 — 2026-11-12

### Добавлено
- Документирована архитектура Workers + D1 + Static Assets.
- Подготовлена ER-модель основной базы и будущих модулей.
- Реализован Cloudflare Worker API для health-check и Telegram webhook.
- Реализована регистрация webhook через защищённый endpoint.
- Добавлено подтверждение согласия через inline-кнопку.
- Добавлена команда `/stop` для отзыва согласия.
- Добавлена защита от повторной обработки Telegram update через таблицу `telegram_updates`.
- Добавлен базовый тёмный интерфейс технического контроля.
- Добавлены SQL- и unit-тесты.

### Ограничения
- Полный модуль управления лидами и сегментами относится к этапам 3–6.
- Импорт/экспорт относится к этапу 7.
- Сбор из внешних Telegram-источников сверх стандартных bot updates не реализован; проверка доступности описана в документации.
- Полноценная web-auth и управление ролями относятся к этапу 10.
